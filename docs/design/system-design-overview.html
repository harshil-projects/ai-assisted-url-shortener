03 Container view and request path

Filter order matters: the rate limiter runs before authentication so API-key guessing is throttled too. Every error, from a filter or a controller, is RFC 9457 Problem Details with a request id.

04 The two flows that matter

Create: POST /api/v1/links

1 filters
Request id assigned. Body over 16 KiB → 413. Bucket empty → 429. Bad key → 401 with WWW-Authenticate.
2 validate
Absolute http/https, host present, no user info, ≤ 2048 chars, host not loopback, private, link-local, or metadata. Optional expiresAt must carry an offset and lie in the future. Violations → 400 with errors[].
3 alias?
If given: regex, reserved list, fast existsByCode → 409 if taken.
4 allocate
Loop ≤ 5: draw a code (or use the alias) → LinkAllocator.insert in its own transaction. Unique violation on uk_links_code: random code → retry; alias → 409.
5 respond
201, Location: /api/v1/links/{code}, body with shortUrl derived from the request host unless app.base-url is set.

Redirect: GET /{code}

1 route
Path pattern {code:[A-Za-z0-9_-]{4,32}}, so favicon and dotfiles never reach the database.
2 lookup
One indexed read by code. Missing → 404. Expired → 410. Both Cache-Control: no-store.
3 hand off
Build immutable ClickRecorded(linkId, now, requestId, attribution) on the request thread, attribution being the Referer host and the utm_* values, cleaned and bounded; offer it to the bounded queue. Full queue → drop and count.
4 respond
302 with Location and explicit no-store. HEAD resolves but is not counted.
5 async
Executor thread inserts one row in its own transaction; failures are caught and counted, never propagated.

05 Short-code algorithm and why

Chosen: random 7-character Base62, uniqueness by the database, bounded retry

alphabet = [0-9A-Za-z] (62 symbols, URL-safe, no escaping)
code = 7 × SecureRandom.nextInt(62)
keyspace = 62^7 = 3,521,614,606,208 ≈ 3.5 × 10^12
birthday bound: E[collisions] ≈ n² / (2 × 62^7)
n = 1,000,000 → ≈ 0.14 expected collisions
n = 10,000,000 → ≈ 14 expected collisions
at 1,000 new links/s the keyspace lasts ≈ 111 years
  • Non-enumerable by construction. Sequential codes can be scanned; the 2016 "Gone in Six Characters" study exposed private cloud documents that way.
  • No extra infrastructure. The INSERT itself enforces uniqueness through the unique index; there is no separate lookup round trip.
  • Collisions are rare but handled, never assumed away: each attempt is its own transaction so a violation cannot poison the request's transaction, and a lost race on a custom alias maps to 409 rather than a retry.
  • SecureRandom is cryptographically strong and thread-safe; one shared instance.

Alternatives and when they win

ApproachProsWhy not here
Base62(counter)No collisions; shortest codes; decodable ids; the Redis INCR design with block reservation scales writes across regionsEnumerable unless obfuscated, and XOR or Hashids obfuscation is reversible; needs Redis; the right switch when many writers need decodable ids
Hash(URL)Deterministic; dedupes repeat URLsCollides and must still be resolved; determinism leaks that two users shortened the same URL unless salted
SnowflakeUncoordinated, time-sortableEncodes to about 11 Base62 chars and leaks creation time and worker id; solves distribution, not shortness
Key generation servicePre-generated blocks, zero collisionsA second service for a single node; listed as the scaling step

No IP, user agent or full referrer URL column; MigrationTest asserts the exact seven-column list

Rules

  • Instant fields map to TIMESTAMP_UTC in Hibernate 7, hence time-zone columns, or startup validation fails.
  • One ALTER per column: H2 and PostgreSQL disagree on the multi-column form.
  • click_events.link_id is a plain column, so a click is one INSERT with no SELECT.
  • No IP, no user agent, no full referrer URL, ever (ADR 0006).
  • Stats = one aggregate query (count, two conditional sums, max) plus two grouped top-ten queries for referrers and campaigns.

Migrations, validated at every start under ddl-auto=validate: V1__create_links_and_click_events.sql (greenfield) · V2__add_link_expiry.sql (brownfield, one ALTER) · V3__add_click_attribution.sql (ambiguous, four single-column ALTERs)

08 Security, reliability, observability

Security

  • Redirect only to the stored, pre-validated URL
  • Internal-host laundering blocked at create
  • API key, constant-time compare, prod fails fast without it
  • Rate limit before auth; body size cap; URL length cap
  • Log sanitiser for user-controlled values
  • Headers: nosniff, DENY, no-referrer, CSP on Swagger only
  • SpotBugs + FindSecBugs, gitleaks, Dependabot

Reliability

  • One transaction per allocation attempt
  • Bounded click executor, drop-and-count, 10 s drain on shutdown
  • 503 + Retry-After within 2 s when the database is unavailable
  • Graceful shutdown, readiness and liveness probes
  • Problem Details from every layer, identical shape

Observability

  • X-Request-Id bounded and echoed; in logs and error bodies
  • Counters: links.created, redirects{outcome}, clicks.dropped
  • Actuator health with database indicator; build info
  • Prometheus endpoint; structured JSON logs in prod
