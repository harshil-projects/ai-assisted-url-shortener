## Title

"Links must be able to expire. Expired links must stop redirecting and must show as expired. Tighten the test suite and docs while there."

## Normalized problem statement

Add an optional absolute expiry time to links on an existing, shipped codebase. A client sets `expiresAt` as an RFC 3339 timestamp with offset at create time; past values and zoneless strings are rejected with 400. Once the time passes, a redirect answers 410 with `Cache-Control: no-store`, the row and its click history stay, and metadata and stats report `expired: true`. The change arrives through a reviewable Flyway migration, is preceded by an engineer-written impact analysis whose predicted file list is checked against the real diff, and is accompanied by a stronger regression suite, a refactor of the top smell found, one real defect fix, and documentation that matches behaviour.

## Functional requirements covered

- FR-13: `expiresAt` accepted as RFC 3339 with offset; past and zoneless values rejected with 400 (T-102)
- FR-14: expired link answers 410 with no-store, row and clicks kept, `expired: true` in metadata and stats (T-102)

## Non-functional requirements covered

- NFR-10 schema change safety: migration V2 as a single-column `ALTER`, validated at startup, proven by `MigrationTest` (T-102)
- NFR-09 testability: coverage not lower than before the change; regression suite added (T-103, T-105)
- NFR-08 maintainability: the top smell named in the impact analysis is refactored with tests unchanged (T-104)
- NFR-11 auditability: predicted versus actual blast radius checked by HC-12 (T-101, T-102)

## Ambiguities identified and reading adopted

| Ambiguity | Reading adopted | Where decided |
|---|---|---|
| "Expire": relative TTL or absolute time | Absolute timestamp supplied by the client with an offset; no TTL field | #3.3, FR-13 |
| "Stop redirecting": 404 or 410, delete or keep | 410 `link-expired` with no-store; the row and its click history are kept | #3.6, ADR-level note in #13 |
| "Show as expired" | Boolean `expired` in `LinkResponse` and `StatsResponse`, plus `expiresAt`; `HEAD` mirrors the status | #3.3 |
| Zoneless timestamps | Rejected with 400 so comparisons are unambiguous; all comparisons in UTC with an injected `Clock` | #3.13 |
| Existing links | `expires_at` is nullable; existing rows never expire | #3.5 |
| "Tighten the test suite" | Regression tests with coverage not lower, one real defect from the T-010 review fixed with a failing-first test | #6.2 |
| "Docs while there" | API reference, changelog, README updated to match behaviour, derived from code and tests | #6.2 |

## Assumptions

- No sweeper or purge; expired rows accumulate and retention is a documented next step (#1.4).
- The brownfield reasoning is written by the engineer first; AI only checks it for omissions.
- A refactor target exists; if the impact analysis finds no smell worth the step, T-104 becomes a tech-debt note per the descoping ladder.
- The T-010 candidate list contains at least one real defect; if not, T-105 is relabelled an enhancement and says so.

## Out of scope

- Active expiry purge, retention deletion, or a scheduler.
- Editing or extending `expiresAt` after creation; reviving an expired link.
- Notifying anyone when a link expires.

## Tasks

T-101 impact analysis; T-102 migration V2 and expiry behaviour; T-103 regression suite and docs; T-104 refactor of the top smell; T-105 one real defect fix with a regression test.
