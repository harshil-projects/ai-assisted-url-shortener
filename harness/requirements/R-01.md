## Normalized problem statement

Deliver a single-node HTTP service that creates short links for validated absolute http or https URLs, redirects on `GET /{code}` with 302 and `Cache-Control: no-store`, records each click off the request thread, and reports per-link totals over all time, 24 hours, and 7 days. Metadata, stats, and delete sit behind one API key on `/api/v1`. Reliability means validation, rate limiting, request size limits, RFC 9457 Problem Details, correlation ids, isolated analytics, graceful shutdown, and 503 with `Retry-After` when the database is unavailable. The whole thing builds and runs on a clean Windows or Linux machine with JDK 21 and no other installs, and every AI-assisted change is traceable through the harness.

## Assumptions

- Single node with embedded H2 in file mode; reviewers have no Docker or admin rights (#1.4).
- Read to write ratio around 10:1, so the redirect path stays minimal and analytics asynchronous.
- One shared API key for a prototype; per-user ownership is a listed limitation.
- Reviewers may run on plain HTTP, so HSTS does not appear locally.

## Out of scope

- User accounts, per-user ownership, audit of who deleted what.
- Link expiry (R-02) and click attribution (R-03).
- Distributed cache, queue, key generation service, rollup tables; scaling path documented only.
- Server-side fetching of target URLs; idempotency keys; load testing; Docker image.
