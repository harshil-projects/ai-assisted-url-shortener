# Prompt v1: greenfield edge (tasks T-007 and the OpenAPI part of T-008)

Executed as one batched generation session alongside the core batch (`harness/prompts/T-002/v1.md`).
The ledger records T-007 and T-008 separately with this prompt as their v1.

## Role and ground rules

You are generating Java 21 / Spring Boot 4.1.1 code for the URL shortener in this repository.
The engineer reviews every file you produce; your output is a draft, not a decision.

Read first: `docs/design/2026-10-12-system-design.md` sections 3.3, 3.4, 3.6 (rate limiting,
request size, API key auth), 3.7, 3.8, 3.9, 4.2, 4.3; then the skeleton under `url-shortener/src`
(`SecurityConfig`, `ApiKeyFilter`, `ProblemDetails`, `ProblemTypes`, `ProblemWriter`,
`AppProperties`, `TestProfile`, `SecuritySmokeIT`, all `application*.properties`). Reuse them.

Hard constraints:

- Spring Boot 4 idioms only: `@MockitoBean` (never `@MockBean`), `tools.jackson.*` (never
  `com.fasterxml.*`), `@AutoConfigureRestTestClient` with `RestTestClient` for full-context tests,
  Spring Security 7 lambda DSL.
- Constructor injection only. Methods under 50 lines, files under 400 lines. Google Java Style (run
  `./mvnw.cmd -B -ntp spotless:apply` before every verify).
- No new Maven dependencies. No edits to `pom.xml`, `config/checkstyle/*`, `SecurityConfig`,
  `ApiKeyFilter`, `ProblemWriter`, `ProblemDetails`, `ProblemTypes`, `AppProperties`. If one of
  these must change, write the proposed change in your final report instead.
- Another session owns the domain, repository, service and controller code and everything under
  `api/dto`. Do not create any of those, and do not create `domain/LogSanitizer` or
  `config/ClockConfig`. You may add springdoc properties to `application.properties` (you are the
  only session allowed to edit properties files).
- Filters are plain classes registered through `FilterRegistrationBean`s in
  `config/FilterRegistrations.java`, never `@Component`, so each runs once. Order: `RequestIdFilter`
  first (`Ordered.HIGHEST_PRECEDENCE`), then `RequestSizeFilter`, then `RateLimitFilter`, all before
  the Spring Security chain (order below `SecurityProperties.DEFAULT_FILTER_ORDER`).
- Never log raw header values; the request id is validated by regex before it is logged.
- Do not run git. Do not create files outside `url-shortener/src`.
- Finish with `./mvnw.cmd -B -ntp verify` green. Fix findings in code; add a SpotBugs exclusion
  only with a written reason in `config/spotbugs/exclude.xml` and mention it in the report.

## Task T-007: request id, request size, rate limiting, security tests

Files: `config/RequestIdFilter.java`, `config/RequestSizeFilter.java`, `config/RateLimitFilter.java`,
`config/FilterRegistrations.java`; tests `RequestIdFilterTest`, `RequestSizeFilterTest`,
`RateLimitFilterTest` (unit with a mocked clock or small capacity), `ApiKeyIT`, `RateLimitIT`,
`SecurityHeadersIT`, `ProblemDetailIT`, `ProdStartupIT`; extend the existing `AppPropertiesTest`.

- `RequestIdFilter` (`OncePerRequestFilter`): read `X-Request-Id`; accept it only if it matches
  `^[A-Za-z0-9-]{1,64}$`, otherwise generate a UUID string; put it in MDC under
  `ProblemDetails.REQUEST_ID`, set the response header `X-Request-Id`, continue, and clear the MDC
  key in `finally`.
- `RequestSizeFilter` applies to paths starting with `/api/v1/`. If `Content-Length` exceeds
  `AppProperties.request().maxBytes()`, write 413 `ProblemTypes.PAYLOAD_TOO_LARGE` through
  `ProblemWriter` without reading the body. If the length is unknown (chunked), read the body up to
  `maxBytes + 1` bytes; over the limit write 413, otherwise continue with a request wrapper that
  replays the buffered bytes (`ServletInputStream` over a `ByteArrayInputStream`, and
  `getReader()` consistent with it).
- `RateLimitFilter` applies to `POST /api/v1/links` only. One Bucket4j bucket per
  `request.getRemoteAddr()` in a Caffeine cache (`maximumSize(10_000)`,
  `expireAfterAccess(10 minutes)`); capacity and period from
  `AppProperties.ratelimit().create()`, greedy refill. On every handled request set
  `X-RateLimit-Limit`, `X-RateLimit-Remaining`; on rejection write 429
  `ProblemTypes.RATE_LIMITED` through `ProblemWriter` with `Retry-After` (whole seconds, at least
  1) and `X-RateLimit-Reset`. Use `tryConsumeAndReturnRemaining(1)`.
- `ApiKeyIT`: missing key 401 with `WWW-Authenticate`, wrong key 401, correct key passes (any
  non-401 status), redirect path `GET /abcdefg` is reachable without a key (404 in this worktree
  because no controller exists yet; assert "not 401"), `/actuator/health` public,
  `/actuator/prometheus` requires the key under the test profile.
- `RateLimitIT` (`@SpringBootTest(properties = "app.ratelimit.create.capacity=3")`): three
  `POST /api/v1/links` with the key get a non-429 status, the fourth gets 429 with `Retry-After`,
  `application/problem+json`, `type` `/problems/rate-limited`; a `GET` is never rate limited.
- `SecurityHeadersIT`: on a redirect-path request and on an API request assert `X-Content-Type-
  Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control`
  contains `no-store`, `X-Request-Id` present and echoed when a valid one is sent, replaced when an
  invalid one (too long or with spaces) is sent; `/swagger-ui/index.html` carries the
  Content-Security-Policy from `SecurityConfig`; `/v3/api-docs` is public and returns JSON.
- `ProblemDetailIT`: the 401, 413 and 429 bodies have the identical shape: `type`, `title`,
  `status`, `detail`, `requestId` equal to the response `X-Request-Id`, `timestamp` parseable as an
  `Instant`; content type `application/problem+json`.
- `ProdStartupIT`: starting the context with `@ActiveProfiles("prod")` and
  `spring.datasource.url=jdbc:h2:mem:prodcheck;MODE=PostgreSQL` but no `app.api-key` fails with a
  `BindValidationException` (or its cause) mentioning `apiKey`; use `SpringApplicationBuilder` or
  `ApplicationContextRunner` so the failure is asserted, not thrown. Keep the test fast.
- `AppPropertiesTest` already covers `hasBaseUrl`; add binding tests: a valid property set binds, a
  blank key fails validation.

## Task T-008 (OpenAPI part): documentation endpoints

Files: `config/OpenApiConfig.java`, `api/OpenApiErrorCustomizer.java`, tests `ActuatorIT`,
`OpenApiIT`; properties appended to `application.properties`.

- `OpenApiConfig`: `OpenAPI` bean with title "URL Shortener API", version from
  `BuildProperties` when available else "0.1.0", a short description, and a `SecurityScheme` named
  `ApiKey` (`type APIKEY`, `in HEADER`, `name X-API-Key`) plus a global `SecurityRequirement` so
  Swagger UI shows the Authorize button. Document that redirects are public in the description.
- `OpenApiErrorCustomizer` implements springdoc `OperationCustomizer` (or `OpenApiCustomizer`):
  adds `401` to operations under `/api/`, and `400`, `404`, `429`, `500`, `503` responses with
  `application/problem+json` content referencing a shared `ProblemDetail` schema (type, title,
  status, detail, requestId, timestamp, errors).
- Properties: `springdoc.api-docs.version=openapi_3_1`, `springdoc.swagger-ui.path=/swagger-ui.html`,
  `springdoc.writer-with-order-by-keys=true`, `springdoc.show-actuator=false`,
  `springdoc.default-produces-media-type=application/json`, and disable the Swagger "try it out"
  petstore defaults (`springdoc.swagger-ui.disable-swagger-default-url=true`).
- `ActuatorIT`: `/actuator/health` 200 with `status UP`, `/actuator/health/liveness` and
  `/readiness` 200, `/actuator/info` with the key returns build info (`build.version` present),
  `/actuator/prometheus` with the key returns text containing `jvm_memory_used_bytes`.
- `OpenApiIT`: fetches `/v3/api-docs.yaml` and compares it with the committed file
  `docs/reference/openapi.yaml` after normalising line endings. If the system property
  `openapi.update` is `true`, write the runtime document to that path and pass; otherwise fail with
  a message telling the reader to run `./mvnw.cmd -pl url-shortener -Dtest=OpenApiIT
  -Dopenapi.update=true test`. The committed file does not exist in your worktree, so the test
  must skip with an assumption (`Assumptions.assumeTrue(Files.exists(...))`) when the file is
  absent; the engineer generates it after merge.
