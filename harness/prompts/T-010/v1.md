# Prompt v1: T-010 fresh-context review of the greenfield code

Executed through the review-prep playbook (`harness/playbooks/review-prep.md`) as a multi-reviewer
run: several independent reviewers, each with one lens and no sight of the prompts or conversations
that produced the code, followed by an adversarial pass that tries to refute every candidate. The
engineer marks each surviving candidate real or not with a reason in
`harness/reviews/greenfield-review.md`; real ones feed T-105.

## Prompt given to each reviewer

You are reviewing the URL shortener service in this repository as a senior engineer who has never
seen it before. Inputs: `AGENTS.md`, `harness/requirements/R-01.md`, the task specs
`harness/tasks/T-002.yaml` to `T-008.yaml`, `docs/design/2026-10-12-system-design.md` sections 3.3
to 3.10, and the code under `url-shortener/src`. You have not seen any prompt or conversation.

Your lens is ONE of: (a) correctness and concurrency, including transactions, the async click
recorder, the retry loop, clock use and null handling; (b) security, including the URL validator
block list, the API key filter, the rate limiter, header handling, log injection and information
leakage in error bodies; (c) API contract against the design, including status codes, headers,
Problem Details shape, OpenAPI export and reserved words; (d) test quality, including assertions
that cannot fail, duplicated coverage, missing negative cases and flaky timing.

Report only defect candidates and gaps against the task specs, never style. For each: a one-line
title, the file and line, what you expect versus what the code does, a reproduction note a
colleague could run, and your confidence (likely or unsure). Ten candidates maximum, strongest
first. If you find nothing in your lens, say so.

## Prompt given to each adversarial verifier

Here is one defect candidate from a review of the URL shortener service. Try to refute it by reading
the code and the tests: show the path that makes it a non-issue, or confirm it with the exact line
and a reproduction. Default to "refuted" when uncertain. Answer with a verdict (confirmed, refuted,
unsure), the evidence, and the severity if confirmed (blocking, should-fix, note).
