Executed as one batched generation session on a worktree of `main` after the greenfield commits.
Each task section is the unit of review; T-103's documentation part and T-105 are executed
separately by the engineer.

## Role and ground rules

You are generating Java 21 / Spring Boot 4.1.1 code in an existing, green codebase (327 service
tests, every gate passing). This is brownfield work: read before you write, change the minimum, keep
every existing test passing without weakening a single assertion.

Read first: `harness/reviews/T-101-impact-analysis.md` (the engineer's impact analysis; your
main-source changes for T-102 must stay inside its "Predicted files" list, a build rule checks it),
`harness/requirements/R-02.md`, `harness/tasks/T-102.yaml`, `T-103.yaml`, `T-104.yaml`,
`docs/design/2026-10-12-system-design.md` sections 3.3 to 3.6 (expiry rows), `AGENTS.md`, and then
the code: `domain/Link`, `service/LinkService`, `service/LinkAllocator`, `service/AnalyticsService`,
`api/LinkController`, `api/StatsController`, `api/RedirectController`, `api/ApiExceptionHandler`,
`api/dto/*`, `repository/*`, the V1 migration, and the tests that cover them.

Hard constraints:

- Boot 4 idioms only (see `AGENTS.md` gotchas). Constructor injection. Records for DTOs with boxed
  types. Methods under 50 lines, files under 400 lines. Run `./mvnw.cmd -B -ntp spotless:apply`
  before every verify.
- No new dependencies; no edits to `pom.xml`, `application*.properties`, `config/checkstyle/*`,
  `config/spotbugs/exclude.xml`, `SecurityConfig`, the filters, `ProblemWriter`, `ProblemDetails`.
- Never delete, skip, rename or weaken an existing test. Existing tests may need new constructor
  arguments; change only what the new signature forces.
- Do not run git. Do not create files outside `url-shortener/src`, `docs/reference/`, and
  `CHANGELOG.md`.
- Finish with `./mvnw.cmd -B -ntp verify` green (format, style, SpotBugs with FindSecBugs at zero,
  JaCoCo 80/70 and no untested class, harness-check). Regenerate the OpenAPI export whenever a
  controller or record changes: `./mvnw.cmd -B -ntp -pl url-shortener -Dtest=OpenApiIT
  -Dsurefire.failIfNoSpecifiedTests=false -Dopenapi.update=true -Djacoco.skip=true test`.

## Task T-102: migration V2 and expiry

Main-source files allowed (from the impact analysis): `V2__add_link_expiry.sql`, `domain/Link`,
`domain/LinkExpiredException` (new), `api/dto/CreateLinkRequest`, `api/dto/LinkResponse`,
`api/dto/StatsResponse`, `api/LinkController`, `api/StatsController`, `api/RedirectController`,
`api/ApiExceptionHandler`, `api/OpenApiErrorCustomizer`, `service/LinkService`,
`service/LinkAllocator`, `service/AnalyticsService`, `repository/LinkRepository`. Touch nothing else
under `src/main`.

- `V2__add_link_expiry.sql`: exactly one statement, `ALTER TABLE links ADD COLUMN expires_at
  TIMESTAMP WITH TIME ZONE`, nullable, with a two-line comment stating the task and why nullable.
- `Link`: nullable `Instant expiresAt` mapped to `expires_at`; constructor gains the parameter; add
  `boolean isExpired(Instant now)` (null means never). Keep equals, hashCode and toString rules.
- `CreateLinkRequest`: optional `Instant expiresAt`. Jackson 3 parses RFC 3339 with an offset into
  `Instant`; a zoneless string fails parsing and must surface as the existing 400
  "Request body is missing or is not valid JSON" with `errors: []` (the handler already does this);
  prove it with a test. A past value is a 400 field error `expiresAt` from `LinkService.create`
  ("expiresAt must be in the future") using the injected clock.
- `LinkService.create` passes `expiresAt` to `LinkAllocator.insert(code, url, now, expiresAt)`.
  `resolve(code)` throws `LinkExpiredException` when `link.isExpired(clock.instant())`; `get(code)`
  returns the link regardless, so metadata shows expired links.
- `LinkResponse` and `StatsResponse` gain `expiresAt` (nullable) and `expired` (boolean, computed
  against the clock when the response is built). `AnalyticsService.stats` keeps counting events of
  expired links.
- `RedirectController`: on `LinkExpiredException` nothing is published and the counter
  `shortener.redirects{outcome=expired}` increments (resolve the exception inside the controller's
  counting helper, rethrow for the handler). `HEAD` behaves the same.
- `ApiExceptionHandler`: `LinkExpiredException` → 410, type `ProblemTypes.LINK_EXPIRED`, title
  "Link has expired", header `Cache-Control: no-store`.
- `OpenApiErrorCustomizer`: add 410 to the operations under `/{code}` only.
- Tests: `MigrationTest.v2AddsNullableExpiresAt`; `ExpiryIT` with a fixed, mutable test `Clock`
  bean (`@TestConfiguration` with `@Primary` or a `MutableClock` in `support/`): create with a
  future expiry → 302 and `expired: false`; advance the clock past it → 410 with
  `Cache-Control: no-store`, metadata `expired: true` with the `expiresAt` echoed, stats still return
  the earlier click counts; `ExpiryIT.rejectsPastAndZoneless`; `RedirectControllerTest` for the
  expired outcome and no event; `LinkServiceTest` for the future check; existing tests updated only
  where the constructor changed.
