Reconstructed record. T-000 created the harness itself, so this prompt could not be committed
before use; it is the instruction the engineer gave the assistant in the interactive session on
2026-10-12, written down for completeness. Every later task's prompt is committed before it runs.

## Instruction given

Using `docs/design/2026-10-12-system-design.md` sections 2.2, 3.1, 3.9, 4.1, 4.5, 5.2 and 5.9 as
the specification:

1. Install nothing system-wide. Use a user-folder Temurin 21 JDK and Maven 3.9.16; generate the
   Maven wrapper pinned to 3.9.16.
2. Create the reactor `pom.xml` (parent `spring-boot-starter-parent` 4.1.1) and the
   `url-shortener` module pom with the exact dependency set from section 3.1 and the plugin set
   from section 4.1. Pin only what the Boot BOM does not manage, at the versions verified on Maven
   Central on 2026-10-12.
3. Add `application.properties` plus `dev`, `prod` and `test` profiles as in section 3.9, the V1
   migration from section 3.5, the application class, a `@TestProfile` meta-annotation and a
   context test proving the migration ran.
4. Write the shared Problem Details support and the stateless API-key security chain from sections
   3.3, 3.4 and 3.7 so both parallel code sessions can build on them, with a smoke test over HTTP.
5. Run `mvnw verify` until every gate is green; record every failure, its cause and the fix.
6. In parallel, draft the custom instructions (`AGENTS.md`, `CLAUDE.md`, the portable copy), the
   secure AI usage policy, playbooks, templates, scripts, the `harness-check` module with rules
   HC-01 to HC-12 and the traceability report, the README, CI, ADRs and the reference documents.
