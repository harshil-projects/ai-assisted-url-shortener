## Defect

`RequestSizeFilter` (413) and `RateLimitFilter` (429) run before the Spring Security chain and
return without calling the rest of the chain, so Spring Security's header writer never adds
`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` or `Cache-Control` to those two
responses. First observed verbatim on the 429 in `docs/fresh-clone-transcript.md`; confirmed by the
review and by the red run.

## Debug record

| Step | Evidence |
|---|---|
| Hypothesis | Filters registered at `DEFAULT_FILTER_ORDER - 20` and `- 10` short-circuit before `HeaderWriterFilter`; `ProblemWriter` sets only the headers the caller passes |
| Regression test first, red | `FilterResponseHeadersRegressionTest`: both tests fail on `X-Content-Type-Options expected nosniff but was empty`; `harness/evidence/T-105/red.log` |
| Smallest fix | `ProblemWriter.write` sets the four headers when absent, with a Javadoc paragraph on why; filters and `SecurityConfig` untouched |
| Green | `harness/evidence/T-105/green.log`; full module verify 419 tests, 0 findings |
