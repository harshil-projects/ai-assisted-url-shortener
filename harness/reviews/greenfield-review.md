## Real defects

Each note is enough to write the failing-first test. "Follow-up" means the engineer lists it in `docs/risks-and-limitations.md` and opens a task for it.

**1, 27. Database outage returns 500.** In `LinkControllerTest`, stub `linkService.create(any())` to throw `new CannotCreateTransactionException("Could not open JPA EntityManager for transaction", new SQLTransientConnectionException("Connection is not available, request timed out after 2000ms."))`. Expect 503, `/problems/service-unavailable` and `Retry-After: 5`; today the response is 500 `about:blank`. For the full stack, start the service with `spring.datasource.url` pointing at a closed port and POST a create. Also check the redirect and metadata paths: design 3.6 places their finder in Spring Data's read-only transaction, which would take the same route. Fix: add `CannotCreateTransactionException` to `handleDatabaseUnavailable`, which means widening its parameter type, and extend the parameters at `ApiExceptionHandlerTest:141`. Fixed by: follow-up.

**2. Redirect shown as authenticated in the export.** Searching `docs/reference/openapi.yaml` for `security` finds only the global block (line 13) and the scheme (line 557). Swagger UI shows a padlock on "Follow a short link". Fix: clear the requirement per operation, for example with an empty `@SecurityRequirements` on `redirect()` and `probe()`. Assert that `/{code}` GET and HEAD carry `security: []`, then re-export. Fixed by: follow-up.

**4. Incomplete error catalogue.** Compare the `POST /api/v1/links` responses in the export (201, 400, 401, 404, 429, 500, 503) with design 3.3 (400, 401, 409, 413, 415, 429, 503). The missing codes are real at runtime: `LinkFlowIT` covers 409 and 415, and `ProblemDetailIT` covers 413. Fix: make the catalogue per operation. Create gets 409, 413, 415 and 429; 429 appears only there; 404 leaves create. Update `OpenApiErrorCustomizerTest:29` and re-export. Fixed by: follow-up.

**5, 12. Two Problem shapes.** `GET /api/v1/links/abcdefg` without a key returns a 401 body with no `instance`. With the key, the 404 body has `"instance":"/api/v1/links/abcdefg"`. A new `ProblemDetailIT` case for that 404 through `assertCanonicalShape` fails on `containsExactlyElementsOf`. Fix: choose one shape. Either `ProblemWriter` sets `instance` from the request URI, with `CANONICAL_MEMBERS` gaining it, or the handler path drops it. Then keep the handler case that design 3.4 names. Fixed by: follow-up.

**8. Reset header.** A valid create returns 201 with `X-RateLimit-Limit` and `X-RateLimit-Remaining` but no `X-RateLimit-Reset`; `RateLimitFilterTest` asserts only the first two. Fix: either set Reset from `probe.getNanosToWaitForReset()` on every create response, or say "429 only" at `api.md:76`. The code route touches the rate limiter, which is high impact; the document route does not. Fixed by: follow-up.

**9. Misplaced rule in `api.md`.** Move the numeric-host sentence from the `customAlias` row (line 30) to the `url` row (line 29). `UrlValidatorTest` already proves `http://2130706433/` fails on field `url` with `MSG_HOST`. Fixed by: follow-up, documentation only.

**10. Leaking integration tests.** Add a throwaway class in the default context that asserts `linkRepository.count()` is zero, then run `.\mvnw.cmd -pl url-shortener "-Dtest=RateLimitIT,ZzzLeakCheckIT" "-Dsurefire.runOrder=alphabetical" test`. It sees 3 rows, or 1 with `ProblemDetailIT`. A related issue: `RedirectIT:42` clears the tables without waiting for the async click insert, which can fail on the foreign key and count a spurious dropped click. Fix: add `@AfterEach` cleanup to both classes, make `LinkFlowIT:138` assert a before-and-after delta, and await the click in `RedirectIT`. Fixed by: T-009, which is in progress and owns the `@AfterEach` constraint, or a follow-up.

**11, 21. Hardening headers on 413 and 429.** The 429 is captured verbatim in `docs/fresh-clone-transcript.md` section 5: it carries `X-Request-Id` and the rate-limit headers, but not `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` or `Cache-Control`. For the 413, POST a 16,385-byte body with the key and inspect the headers. Regression test: send that body and exhaust a capacity-1 bucket, then assert `nosniff`, `DENY` and `no-referrer` on both responses. Fix direction: write the headers on the filters' rejection path, for example in `ProblemWriter`. Moving both filters behind the chain's header writer would change the "limiter before authentication" ordering. Fixed by: T-105. The fix touches headers, a design 5.6 security surface, and `T-105.yaml` still says normal impact; its own constraint requires re-classification to high with reason `security`.

**13, 30. No real-database collision test.** Write a `@SpringBootTest` with `@MockitoBean CodeGenerator`. Pre-insert code `taken01`, stub `next()` to return `taken01` and then `fresh02`, and POST a create. Expect 201 with code `fresh02` and two generator calls. For the alias race, spy `LinkRepository.existsByCode` to return false for an alias already stored, POST it, and expect 409 `alias-taken`. Fix: add both tests. Then either name one `aliasRaceMapsTo409` or correct the verification in `T-004.yaml` and the FR-03 row of the design. Fixed by: follow-up.

**14. Request id on the click event.** In a full-context test, add a synchronous `@EventListener` that captures `ClickRecorded`. Send `GET /{code}` with `X-Request-Id: trace-77` and assert that `requestId()` equals `trace-77`. Today no test fails if `RedirectController:110-111` passes `null`. Fixed by: follow-up.

**15. Drift gate can skip.** Move `docs/reference/openapi.yaml` aside and run `.\mvnw.cmd -pl url-shortener -Dtest=OpenApiIT test`: `committedSpec_matchesRuntime` is reported as skipped and the build passes. Fix: replace `assumeTrue` with a failing assertion that names the update command. Fixed by: follow-up.

**18. Statement counts unproven.** In a `@DataJpaTest` with `spring.jpa.properties.hibernate.generate_statistics=true`, unwrap the `SessionFactory` statistics. Assert one prepared statement across saving and flushing a `ClickEvent`, and one across `summarize`. Fixed by: follow-up.

**20. Key guessing beyond creates.** Send 500 `GET /api/v1/links/abcdefg` requests from one address, each with a different wrong `X-API-Key`. All return 401 and none returns 429; `RateLimitIT:76` pins that reads are never limited. There are two fix routes. One counts failed authentications per client address on every key-checked path and answers 429 past a threshold. The other narrows the claims in design 3.7, NFR-05, ADR 0007, the threat model and `AGENTS.md` to create flooding, and enforces a minimum key length in the prod `AppProperties`. Either route touches a 5.6 security surface. Fixed by: follow-up.

**22. `.localhost` names.** POST `{"url":"http://admin.localhost:8080/"}` with the key: 201. Add `http://foo.localhost/` and `http://a.b.localhost./` to `UrlValidatorTest` expecting `MSG_BLOCKED_HOST`; both fail today. Fix: in `isBlockedHost`, also block names ending in `.localhost` after trailing-dot removal, and add the rule to design 3.6. Fixed by: follow-up, high impact with reason `security`.

**26. Firewall rejections.** Run `curl.exe -si "http://localhost:8080//abcdefg"` and `curl.exe -si "http://localhost:8080/abcdefg;x=1"`. Expected today: 400 with `Content-Type: application/json`, Boot's default body, and no `type` or `requestId`. This was not run for this review; it is derived from the missing handlers. Fix: add a `RequestRejectedHandler` bean that writes through `ProblemWriter`, plus an error controller that renders Problem Details for anything else reaching `/error`. Fixed by: follow-up, high impact with reason `security`.

**28. Delete race.** Write a `@SpringBootTest` that creates a link, then sends two `DELETE /api/v1/links/{code}` calls with the key from two threads released by one `CountDownLatch`. Expect one 204 and one 404. Expected today: one 204 and one 500, plus an "Unhandled exception" log with a stale-state cause. This is derived from the code path, not run. Fix: replace the derived method with `@Modifying @Query("delete from Link l where l.code = :code")` returning the affected-row count; the database cascade still removes the click events. Fixed by: follow-up, high impact with reason `data-deletion`.

**29. Async wiring unproven.** Add two cases to `ClickRecordingIT`. First, record the thread name inside the spied `ClickEventRepository.save` and assert it starts with `click-recorder-`. Second, take the `clickRecorderExecutor` bean, block its four threads and fill its 1000-slot queue, then `GET /{code}`. Assert 302 within a timeout and `shortener.clicks.dropped` with `reason=saturated` up by one. Nothing in the default suite checks the thread today. Fix: add both tests, and correct the verification name in `T-005.yaml` and in design FR-07 and 3.13. Fixed by: follow-up.

One further observation, not counted in the totals: none of the twelve method-level names in the verification lists of T-004 to T-008 matches a test method in `url-shortener/src/test`. Examples are `LinkFlowIT.createsLinkAndReturns201` and `OpenApiIT.committedSpecMatchesRuntime`; the tests themselves use `method_scenario_expectedOutcome` names. harness-check requires only a non-empty list (`TaskSpecChecks.java:39`), so traceability by test name does not resolve for these tasks.

Rows 1 and 27, 5 and 12, 26 and 28 depend on framework behaviour traced through code; their failing-first tests are the confirmation.
