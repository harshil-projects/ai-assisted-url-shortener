# AI-Assisted URL Shortener

A URL shortener built by one engineer with AI assistance. Every change is reviewed, gated, and traceable.

This repository answers the assignment brief for an AI-assisted software engineering role. The engineer wrote the requirements, task specs, and prompts. The AI drafted code, tests, and documents inside those tasks. The engineer reviewed every diff, kept or rejected each file with a written reason, ran the quality gates, signed off on high-impact changes, and committed. Nothing was handed to an autonomous loop. The process itself is data under `harness/`, and a JUnit module fails the build when that data has a gap.

## Run it in three commands

You need JDK 21 on `JAVA_HOME` and nothing else. The Maven wrapper fetches Maven and all dependencies on first use. The second command keeps running; use a second terminal for everything after it.

PowerShell:

```powershell
git clone https://github.com/harshil-projects/ai-assisted-url-shortener.git C:\dev\shortener; cd C:\dev\shortener
.\mvnw.cmd -pl url-shortener spring-boot:run
start http://localhost:8080/swagger-ui.html
```

bash:

```bash
git clone https://github.com/harshil-projects/ai-assisted-url-shortener.git ~/dev/shortener && cd ~/dev/shortener
./mvnw -pl url-shortener spring-boot:run
xdg-open http://localhost:8080/swagger-ui.html   # macOS: open http://localhost:8080/swagger-ui.html
```

In Swagger UI press **Authorize** and enter `dev-only-key-do-not-use`. That key is the dev profile default and is valid nowhere else.

## Verify in five minutes

Run these in a second PowerShell window while the service is up. `curl.exe --%` makes PowerShell pass the rest of the line verbatim, so the JSON quoting works on PowerShell 5.1 and 7 alike.

1. Health.
   ```powershell
   curl.exe -s http://localhost:8080/actuator/health
   ```
   Expect a body that starts with `{"status":"UP"`.
2. Create a link with a custom alias.
   ```powershell
   curl.exe --% -i -X POST http://localhost:8080/api/v1/links -H "Content-Type: application/json" -H "X-API-Key: dev-only-key-do-not-use" -d "{\"url\":\"https://example.com/docs\",\"customAlias\":\"demo-link\"}"
   ```
   Expect `HTTP/1.1 201`, `Location: /api/v1/links/demo-link`, and a JSON body with `code`, `shortUrl`, `url`, and `createdAt`.
3. Follow the short link.
   ```powershell
   curl.exe -i http://localhost:8080/demo-link
   ```
   Expect `HTTP/1.1 302`, `Location: https://example.com/docs`, and `Cache-Control: no-store`. The service never contacts example.com.
4. Read the stats.
   ```powershell
   curl.exe -s -H "X-API-Key: dev-only-key-do-not-use" http://localhost:8080/api/v1/links/demo-link/stats
   ```
   Expect `"totalClicks":1`. Clicks are recorded off the request thread, so repeat once if the count is still 0.
5. Call the management API without a key.
   ```powershell
   curl.exe -i http://localhost:8080/api/v1/links/demo-link
   ```
   Expect `HTTP/1.1 401`, `WWW-Authenticate: ApiKey realm="url-shortener"`, and an `application/problem+json` body.
6. Request a code that does not exist.
   ```powershell
   curl.exe -i http://localhost:8080/no-such-code
   ```
   Expect `HTTP/1.1 404` with a Problem Details body.
7. Delete the link so the sequence can be repeated.
   ```powershell
   curl.exe -i -X DELETE -H "X-API-Key: dev-only-key-do-not-use" http://localhost:8080/api/v1/links/demo-link
   ```
   Expect `HTTP/1.1 204`.

`.\scripts\demo.ps1` runs the same sequence plus a 429 check through `Invoke-RestMethod`, printing status codes and headers, with no quoting tricks.

## Reviewer environment notes

Assumed: a locked-down Windows laptop, JDK 21, no Docker, no admin rights, possibly a corporate proxy. Linux and macOS behave the same with `./mvnw`.

| Situation | What to do |
|---|---|
| `JAVA_HOME` points at JDK 8 or 17 | The build stops at once with an enforcer message naming the required range. Point this shell only at JDK 21 with the override below; no admin rights needed |
| No admin rights to install Java | Download the Temurin 21 JDK zip from adoptium.net and extract it under `C:\dev`. The override below assumes the folder is `C:\dev\jdk-21` |
| Corporate proxy blocks Maven Central | Add the proxy block below to `%USERPROFILE%\.m2\settings.xml`. The wrapper fetches Maven itself through the Windows system proxy; Maven fetches dependencies through this file |
| TLS inspection fails downloads with PKIX errors | Run `$env:MAVEN_OPTS="-Djavax.net.ssl.trustStoreType=Windows-ROOT"` first so the JVM trusts the Windows certificate store |
| The wrapper cannot download Maven at all | Download `apache-maven-3.9.16-bin.zip` from maven.apache.org, extract it, and run its `bin\mvn.cmd` with the same arguments in place of `mvnw.cmd` |
| The first build is slow | Expect 10 to 25 minutes on an empty cache and under two minutes afterwards. `.\mvnw.cmd -o verify` runs fully offline once the cache is warm |
| Port 8080 is taken | Run `$env:SERVER_PORT=9090` before the run command. `shortUrl` values follow the port you chose |
| Windows Defender Firewall asks about java.exe | Cancel the prompt. Traffic to localhost works without it |
| example.com is blocked by the proxy | The 302 and its `Location` header are the evidence. The hop after that belongs to the browser, not the service |
| Long paths or OneDrive sync | Clone to a short path such as `C:\dev`, outside any synced folder |
| `curl` prints PowerShell errors | In PowerShell `curl` is an alias of `Invoke-WebRequest`. Use `curl.exe` as written |
| Wrong profile | `dev-only-key-do-not-use` is valid in the dev profile only. The prod profile refuses to start unless `APP_API_KEY` is set |

Session-only JDK override, PowerShell:

```powershell
$env:JAVA_HOME="C:\dev\jdk-21"; $env:Path="$env:JAVA_HOME\bin;$env:Path"
```

Session-only JDK override, cmd:

```cmd
set JAVA_HOME=C:\dev\jdk-21
set Path=%JAVA_HOME%\bin;%Path%
```

Proxy block for `%USERPROFILE%\.m2\settings.xml`, with the host and port of your proxy:

```xml
<settings>
  <proxies>
    <proxy>
      <id>corporate</id>
      <active>true</active>
      <protocol>https</protocol>
      <host>proxy.corp.local</host>
      <port>8080</port>
      <nonProxyHosts>localhost|127.0.0.1</nonProxyHosts>
    </proxy>
  </proxies>
</settings>
```

## Engineer accountability

Harshil is accountable for every line in this repository. AI output was treated as a suggestion: reviewed, tested, and understood before it was kept, and rejected with a written reason when it was not. The AI was never the final arbiter of a design, a dependency, a test, or a merge. Assistance is disclosed per task in `harness/ledger.yaml`, which names the tool, the model, the prompts, the raw output, and the decision for every file. Commit messages carry only a `Task:` trailer that resolves to that entry.
